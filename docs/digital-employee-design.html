一、结论先行

数字员工不需要新建角色。Octop 里已经有两个可复用的东西：团队那套 agent 无关的自治运行时，和 expert 的人格模板。缺的是把它们解耦——让「单兵 expert + 自主运行」这个格子存在——再补上岗位层（职责 / 权限 / 预算 / 考核 / 汇报线）。

二、判据：状态机什么时候是必须的

状态机的必要性不来自「工作流复杂」。多步骤不等于需要状态机——一条 20 步的流水线不需要，每步都有可观测的完成信号。

状态机真正解决两件事：

条件含义不满足会怎样
(a) 承诺必须活得比做出承诺的进程久。一个决策单元跨越 heartbeat → 决策 → 派发 → 成员跑 → 回叫 → 审批 → 恢复 → 结算；这个跨度里进程会死、会重启，LLM 没有记忆。 状态存在内存里 → 重启即丢 → 承诺变成谎言
(b) 有第二个 actor 会碰它。团队协调器写、host 工具写、Dashboard 拖拽写、sweeper 写、成员回叫写、审批人写。 多写者并发覆盖 → 静默丢失 / 互相打架

满足 (a) 或 (b) 之一 → 需要一个持久的状态记录（可能只是一张表几个字段，不需要迁移表）。两者都满足 → 才需要真正的状态机（封闭的合法迁移集）。

② 只有 version == 22 有专用幂等分支（migrate.py:2336-2348），23/24 直跑原始文件 → 裸 ALTER 放进 023/024 会在「版本回退后重跑」时炸 duplicate column name。

而 022 三处正好合适：已经承载 team 看板的全部表（数字员工正是为复用它们而加列）、其分支走幂等 helper 而非原始文件（SQLite 侧根本不执行裸 ALTER）、本就是本分支的未发布大杂烩迁移（MiniApps + team 看板 + usage_log.team_id + cron_jobs.meta）。

幂等 helper 是真正的保证，挂在两处：version == 22 分支 + run_migrations 的 post-loop 无条件块（覆盖「已记录版本、文件被跳过」的库）。

6.2 DDL

-- 数字员工：自治开关（默认关；打开即视为数字员工） ALTER TABLE agents ADD COLUMN autonomy_enabled INTEGER NOT NULL DEFAULT 0; -- 岗位规格：自治策略（加列，不改表名） ALTER TABLE proactive_care_config ADD COLUMN budget_limit_tokens INTEGER NOT NULL DEFAULT 0; ALTER TABLE proactive_care_config ADD COLUMN budget_window TEXT NOT NULL DEFAULT 'day'; ALTER TABLE proactive_care_config ADD COLUMN sla_tasks_per_day INTEGER NOT NULL DEFAULT 0; ALTER TABLE proactive_care_config ADD COLUMN escalate_to TEXT NOT NULL DEFAULT ''; ALTER TABLE proactive_care_config ADD COLUMN responsible_scope TEXT NOT NULL DEFAULT ''; ALTER TABLE proactive_care_config ADD COLUMN tool_scope_allow TEXT NOT NULL DEFAULT ''; ALTER TABLE proactive_care_config ADD COLUMN tool_scope_deny TEXT NOT NULL DEFAULT '';
这些裸 ALTER 不能是唯一入口。run_migrations 会跳过 version <= current 的文件（migrate.py:2442），而 _apply_sqlite_migration 只对 version == 22 走幂等 helper 分支（:2336-2348）。一个已经记录了该版本的本地库会永远拿不到这些列。

必须有一个幂等 helper（_ensure_autonomy_schema），挂在两处：version == 22 分支（让该分支应用完整的 v22 schema）＋ run_migrations 的 post-loop 无条件块（覆盖「已记录版本、文件被跳过」的库）。

用既有的 _ensure_column / _table_columns 工具（migrate.py:92-117）——它先查列是否存在，跨方言安全。

✅ 已实施：022_light_apps.sql / .pg.sql（裸 ALTER / IF NOT EXISTS）+ migrate.py helper + tests/unit/db/test_autonomy_schema.py（6 例，含「版本回退重跑」与「已记录版本修复」两个关键路径）。
