DECISIONS 01–05

决策日志（上）

布局、权限、外部数据、公开实时、事件
#决策点结论
1 Board 布局 12 列自由网格 + react-grid-layout；服务端存 {x,y,w,h}，保存做 CAS。
2 对外看板权限 每个应用必须已发布；看板 token 只授权布局，未发布单元格显示占位。
3 实时外部数据 先通用 http-extract + URL 白名单，豆瓣 adapter 后置。
4 公开实时 结构化 adapter + 缓存优先 + 限流；通用 http-extract 只服务登录态。
5 事件范围 复用 infra/events，分阶段；MVP 做 inbox + webhook + Agent 通知，渠道直投后置。
决策 4 的顺序影响：I1a 通用服务（登录态） → I1b 豆瓣 adapter + public_live（公开实时）；I1b 可整体滑到 R3。
DECISIONS 06–09

决策日志（下）

调度、迁移、IM、发布节奏
#决策点结论
6 定时任务 新建 light_app_schedules + 扩展 AppSourceScheduler；cron + 服务器时区；迁移 schedule_seconds。
7 跨主机迁移 Bundle v2：内容 + 声明，不带凭据/token；目标机重新绑定 connector，调度默认停用。
8 IM 全功能 先 owner 认证链接，后渠道身份绑定；私聊 owner 发一次性链接，群聊/非 owner 只读。
9 发布节奏 R1 / R2 / R3 三个独立里程碑；每阶段可独立合并、验收、回滚。
安全边界

公开面只读；页面不能指定投递目标或任意 URL。

兼容边界

旧应用全开；旧发布回退实时；旧 schedule_seconds 自动迁移。

可滑档项

I1b 豆瓣 adapter + 公开实时可整体从 R2 滑到 R3。

INVARIANTS

架构不变量

新增需求也不能破坏的 7 条
01

页面是无状态 iframe

没有每应用进程、没有本地端口、没有 JWT；所有外部 I/O 由宿主代调。

02

凭据只在服务端

页面拿到数据或短期能力，不拿 connector token、IM token、发布 token。

03

能力先声明后使用

external.fetch、events.emit、chat.compose、ai.generate 都进 manifest。

04

一个事件面

扩展 infra/events，不新建第二套事件总线。

05

一个 App 调度器

light_app_schedules 统一应用级定时任务，替代 schedule_seconds。

06

一个连接器通道

GatewayToolRunner + catalog adapter；不开放页面任意 URL。

07

公开面只读且可缓存

公开链接/看板不写数据；公开实时仅限结构化 adapter + 缓存优先 + 限流。

R1 · F1

页面能力清单

能力只约束页面，不约束宿主 UI 和 Agent 工具
能力新应用默认旧应用强制点
data.read开开宿主 bridge
data.write开开仅 bridge（详情页数据面板也走 POST /rows）
asset.read / external.open / chat.compose / events.read开开宿主 bridge
ai.generate关开bridge + 服务端 /generate
game.launch关开bridge + 服务端 /game-sessions

R1 · F2

发布快照：数据实时，结构冻结

公开链接不再随 Agent 编辑而静默改变

实时

兼容

↓

R1 · F3 / F4 / F5

交互、边界与恢复

三个小能力，补齐体验与安全
F3 · composeMessage

应用 → 输入框

  • 页面调用 octopApp.composeMessage(text)
  • 宿主预填聊天输入框，不自动发送
  • 复用现有 prefillInput 机制

F4 · 限流

应用级 + 公开

  • 每应用 2 个并发 LLM 调用
  • 每应用 30 次/分钟
  • 公开链接 120 次/分钟 per token+IP
  • 超限 APP_BUSY（429）+ Retry-After
F5 · 回滚

上一版 HTML

  • 覆盖前保存 previous_html
  • POST /apps/{id}/restore-html
  • edit_structure + 审计
  • 公开链接需重新发布才更新
注意：限流是每进程的；多实例下是每实例限流，文档需注明，不为此引入分布式锁。

R2 · I1

实时外部数据：宿主代调

页面永远不直接访问外部服务
页面 octopApp.service("douban").call("get_book", {isbn})
↓
宿主 bridge · 检查 external.fetch + 服务声明
↓
POST /apps/{id}/services/{name}/call
↓ 工具白名单 / 参数 schema / URL 前缀
GatewayToolRunner → connector adapter
↓
缓存 JSON / 封面存 asset → 返回页面
安全

只读工具；SSRF 校验；响应 ≤5MB；超时 20s；每服务限流；无凭证进页面。

封面

服务端拉取图片 → assets/ → asset 名；页面用 octopApp.asset()。

公开

只读缓存；I1b 只允许结构化 adapter + public_live + 缓存优先 + 限流。

禁止：通用 http-extract 不参与公开实时；公开页不能传任意 URL；页面不能指定 connector 实例。
R2 · I2 / I3

事件进出：复用现有事件面

不重写 outbox · 不新建第二套总线
入站 · app.inbox
外部 webhook / connector poll
↓
infra/events 订阅过滤 + 去重 + 重试
↓
light_app_events（收件箱）
↓
页面 events() / onEvent()
出站 · emitEvent
页面 emitEvent(type, payload)
↓
POST /apps/{id}/events · events.emit
↓
隐藏 app source → 订阅 → delivery/retry
↓
webhook / Agent 通知（渠道后置）
SDK：events / onEvent / emitEvent；宿主 5–10 秒轮询。
目标：owner 配置，页面不能指定；webhook HMAC + 私网校验。
边界：payload ≤64KB；每 app 30 条/分钟；保留 30 天 / 500 条。
R2 · I4

统一定时任务

一个 App 入口 · cron + 服务器时区
light_app_schedules (
  schedule_id, app_id, name,
  action, payload_json,
  schedule_spec, timezone,
  next_run_at, lease_until,
  last_run_at, last_status
)
复用：APScheduler CronTrigger 计算 next_run；30 秒扫描 + 条件 UPDATE 租约，多实例只执行一次。
动作

sync_source · snapshot_publication；P2 加 run_agent、refresh_service_cache。

迁移

schedule_seconds > 0 自动生成 sync_source 调度，停止扫描旧列，保留一个版本。

UI

App 详情“自动化”页签；cron 预设、下次运行、最近状态、启用/停用、立即运行。

工具

app_schedule_create/list/update/delete/run_now。

不改 cron_jobs：避免 SQLite CHECK 约束重建和 Agent 回合语义耦合；App 侧只保留一个调度入口。
R2 · P3

对外看板

看板 token 只授权布局，不绕过应用发布
规则

每个单元格检查该 app 是否有有效发布快照；未发布显示占位。

只读

无写入、无事件、无任意 URL；公开实时仅限 public_live + 结构化 adapter。

撤销

Board token 可撤销/轮换；Cache-Control: no-store；按 token+IP 限流。

看板 token
↓
读取 layout + 每个单元格的 app 发布状态
↓
已发布 → 快照 HTML + 实时行
↓
未发布 → “未发布”占位
分享体验：提供“批量发布看板内应用”的便捷操作；授权仍落在每个应用上，撤销仍然有效。
